# SafetyHack — WebRTC-звонки с анализом речи

Звонящий открывает веб-страницу, получатель — Android-приложение или вторую веб-страницу. Звук идёт через WebRTC. Получатель отправляет копию **удалённой дорожки звонящего** на сервер: PCM → faster-whisper → текст → демонстрационные правила риска.

**Для звонков используется WebRTC; телефонный номер не нужен.** Это интернет-звонок внутри нашего продукта, не запись SIM/Telegram-звонков и не переадресация. Оба участника должны разрешить анализ. Низкий риск не означает безопасность.

## Границы MVP

- Одна комната, два участника (`caller` и `receiver`), один процесс сервера и один ASR-слот.
- Android — защищённая оболочка WebView над WebRTC-клиентом; нужен актуальный Android System WebView.
- **Получатель держит приложение открытым.** Сворачивание, блокировка, поворот и Back завершают сессию. Фонового push-вызова нет.
- Ключ и согласие — только в памяти страницы. В Android сохраняется только адрес сервера.
- Общий `SAFETY_TOKEN` знают оба доверенных тестовых участника. Это не публичный многопользовательский сервис; не публикуйте ключ вместе со ссылкой.
- STUN не заменяет TURN: некоторые NAT/мобильные сети не установят прямую связь. Бесплатный TURN проект не предоставляет.
- Потеря ASR явно отмечается; звук может продолжаться. Потеря сигналинга завершает звонок. Пропущенные фрагменты не восстанавливаются.
- Whisper: окна 4 секунды, перекрытие 1 секунда, максимум 15 минут анализа. Tiny ошибается; скорость на Render Free не подтверждена.

## Запуск на этом компьютере

PowerShell из корня:

```powershell
cd D:\hackaton\SAFETYHACK
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Параметры — [.env.example](.env.example):

```dotenv
SAFETY_TOKEN=ЗАМЕНИТЕ_СЛУЧАЙНЫМ_КЛЮЧОМ_НЕ_КОРОЧЕ_16_СИМВОЛОВ
PUBLIC_BASE_URL=
RTC_ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"}]
ASR_MODE=whisper
ASR_MODEL=tiny
ASR_DEVICE=cpu
ASR_COMPUTE_TYPE=int8
```

Случайный ключ: `[guid]::NewGuid().ToString('N')`. Секреты не коммитить и не присылать в чат. Существующий `.env` автоматически не переписывается.

На этом компьютере зависимости и модель `.models/manual-tiny` уже установлены:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File server/run.ps1 -Mode whisper -Model .models/manual-tiny -Port 8001
```

На новом компьютере установите зависимости из [requirements-asr.txt](server/requirements-asr.txt). Для проверки только связи используйте `-Mode diagnostic`: **распознавания и оценки риска не будет**. Аргументы запуска задают ASR-режим/модель/устройство поверх `.env`.

При пустом `PUBLIC_BASE_URL` разрешены localhost-origin:

- Звонящий: `http://localhost:8001/rtc?role=caller`.
- Получатель: `http://localhost:8001/rtc?role=receiver`.
- Проверка: `http://localhost:8001/health`.

Для физического Android нужен доверенный **HTTPS**, не локальный HTTP/IP. Используйте Render или HTTPS-туннель на порт 8001. Запишите точный HTTPS-origin в `PUBLIC_BASE_URL`, перезапустите сервер и открывайте обе страницы через этот домен. При заданном публичном адресе localhost-сигналинг намеренно отклоняется.

## Бесплатный Render

Подготовлены [render.yaml](render.yaml) с `plan: free` и [Dockerfile](server/Dockerfile). Аккаунт/сервис здесь не создавались, платные ресурсы не покупались.

1. Загрузите проект в свой Git-репозиторий **без** секретов, `.tools`, `.venv` и локальных моделей.
2. Создайте Render Blueprint из репозитория либо Web Service: Dockerfile `server/Dockerfile`, context — корень, тариф **Free**, health check `/health`.
3. Blueprint генерирует `SAFETY_TOKEN`. При ручном создании задайте собственный ключ в Environment.
4. `PUBLIC_BASE_URL` — реально назначенный HTTPS-origin вида `https://your-service.onrender.com`, без пути. Если адрес ещё неизвестен при создании Blueprint, временно задайте HTTPS-origin, затем исправьте и выполните redeploy **до теста**.
5. Оставьте `ASR_MODE=whisper`, `ASR_MODEL=tiny`, `ASR_DEVICE=cpu`, `ASR_COMPUTE_TYPE=int8`. Docker скачивает tiny при сборке, не при первом звонке.
6. Дождитесь успешного `/health`, откройте `/rtc?role=caller`. В Android укажите только HTTPS-origin.

Контейнер слушает `0.0.0.0:$PORT`, один worker. TLS/WSS обеспечивает Render. Несколько workers/экземпляров не поддерживаются: комнаты находятся в памяти процесса.

**Free не гарантирует достаточных ресурсов:** 512 МБ RAM и 0,1 CPU могут не обеспечить Whisper в реальном времени или вызвать завершение по памяти. Развёртывание на вашем Render пока не проверено. При OOM временно поставьте `ASR_MODE=diagnostic` для проверки звонков — это не исправление распознавания. Бесплатный вариант с анализом: собственный компьютер и HTTPS-туннель. Разделение Render-сигналинга и отдельного ASR-сервера пока не реализовано.

Перед демо разбудите сервис через `/health` и дождитесь готовности. Обновление/перезапуск обрывает звонки. Официально: [Free](https://render.com/docs/free), [WebSockets](https://render.com/docs/websocket), [Docker](https://render.com/docs/docker).

## Android и первый звонок

[APK 0.3-webrtc](android/app/build/outputs/apk/debug/app-debug.apk); Firebase-конфигурация **не нужна**. Сборка и ограничения: [android/README.md](android/README.md).

1. Установите новый APK поверх прежнего. На Vivo задайте доверенный HTTPS-origin сервера. При «Сохранить и открыть» разрешите микрофон системе — до открытия страницы.
2. Получатель вводит комнату (8–64 латинских букв/цифр, `_` или `-`) и `SAFETY_TOKEN`, подтверждает согласие и подключается.
3. Звонящий открывает `https://ВАШ-ДОМЕН/rtc?role=caller`, вводит **ту же комнату и ключ**, подтверждает согласие и подключается.
4. Звонящий вызывает; получатель отвечает. Android отдельно запрашивает согласие на микрофон для доверенной страницы; системное разрешение уже получено на первом шаге.
5. Проверьте двусторонний звук. При блокировке автопроигрывания нажмите кнопку включения звука.
6. Звонящий произносит «Переведите деньги на безопасный счёт». У получателя ожидаются текст и предупреждение; не используйте настоящие коды и персональные сведения.
7. Проверьте отклонение/отмену, завершение с обеих сторон, mute, повторный звонок, потерю сервера, закрытие страницы и сворачивание Android.

Для двух страниц на одном компьютере используйте наушники, избегайте акустической петли. Такой тест не доказывает работу Vivo или разных сетей.

## Если сигналинг работает, а звук не соединяется

Возможно, нужен TURN. В `RTC_ICE_SERVERS_JSON` можно задать собственный:

```dotenv
RTC_ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"turns:YOUR-TURN-HOST:5349","username":"YOUR-USER","credential":"YOUR-TURN-PASSWORD"}]
```

Это заглушки, не бесплатный работающий TURN. Авторизованные участники получают ICE-учётные данные: используйте ограниченные credentials, не административный ключ. Не отключайте TLS/Origin ради подключения.

## Проверки и безопасность

### Диагностика распознавания в логах сервера

Логи уровня INFO включены через логгер Uvicorn, дополнительная переменная окружения не нужна. После обновления сервера смотрите Render → Logs:

- `ASR_STARTUP` — выбранный режим; `ASR_MODEL_LOADING` → `ASR_MODEL_READY` — модель действительно загружена, указано время загрузки. `ASR_MODEL_LOAD_FAILED` — ошибка загрузки.
- `RTC_AUDIO_SOCKET` — открыто соединение, но старт/авторизация ещё не подтверждены. `RTC_AUDIO_READY` — формат и одноразовое разрешение приняты; `asr_enabled=True` означает доступный распознаватель.
- `RTC_PCM_FIRST` — первый принятый PCM, размер и громкость `dbfs`. Если есть READY, но нет PCM_FIRST, звук не поступает с клиента.
- `RTC_AUDIO_PROGRESS` каждые 5 секунд — число пакетов, секунды аудио, размер буфера, очередь, время без PCM и длительность текущего распознавания. Нулевая очередь сама по себе не означает отсутствие активной обработки.
- `ASR_WINDOW_SKIP reason=silence` — окно тише порога −55 dBFS. `asr_disabled` — распознавание отключено.
- `ASR_INFERENCE_START` → `ASR_SEGMENTS` → `ASR_INFERENCE_DONE` — запуск, число сегментов/отфильтрованных сегментов/секунды после VAD и завершение. `empty=True` означает пустой результат; `realtime_ratio` больше 1 означает обработку медленнее длительности окна.
- `ASR_RESULT_SENT` — текст и оценка отправлены клиенту (это не подтверждение отображения на экране).
- `ASR_INFERENCE_FAILED` / `RTC_AUDIO_FAILED` — тип исключения и безопасные места стека. `QueueFull` означает переполнение очереди. `RTC_AUDIO_BUSY` — слот пока занят.
- `RTC_AUDIO_CLOSING` / `ASR_SLOT_RELEASED` — закрытие сессии и фактическое освобождение обработчика. Обработка может завершиться позже закрытия сокета.

Короткий случайный `trace` связывает события одной аудиосессии. Ключи, tickets, комнаты, SDP, аудио и распознанный текст не записываются. Сообщения исключений намеренно скрыты, поскольку могут содержать чувствительные данные. Эти логи диагностируют цепочку, но не исправляют недостаток ресурсов или ошибки распознавания.

.\.venv\Scripts\python.exe -m pytest -q

Фактические результаты — [VALIDATION.md](VALIDATION.md). Автотесты не заменяют разговор на Vivo.

Необязательный браузерный smoke (нужны локальный Chrome и Node Playwright):

```powershell
# Терминал 1: отдельный localhost-сервер, искусственный ASR, без .env/секретов.
.\.venv\Scripts\python.exe -m tests.rtc_browser_smoke --serve-only --slow-first-asr
# Терминал 2: подставьте напечатанный адрес вместо PORT и путь к своему playwright.
node tests/rtc_browser_smoke.cjs /ABS/PATH/TO/node_modules/playwright http://localhost:PORT --busy-redial
```

Этот тест создаёт звуковые тоны и проверяет передачу удалённой дорожки, повторный вызов, busy-retry и очистку. Не измеряет точность Whisper; после проверки остановите тестовый сервер Ctrl+C.

- Сигналинг `/ws/rtc`: ключ в первом JSON по WSS, не в URL. Проверяются Origin, комната, роль, согласие и состояние звонка.
- PCM `/ws/rtc-audio`: одноразовый ticket получателя после принятия звонка. Присланное клиентом аудио не является доверенным доказательством слов человека.
- Сервер не сохраняет аудио/текст на диск. Старый микрофонный тест сохраняет локальный WAV.
- WebRTC шифрует транспорт, но получатель намеренно передаёт удалённый голос серверу для анализа. Это не обещание доступа только двух участников к содержимому.
