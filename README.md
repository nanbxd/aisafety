# SafetyHack — WebRTC-звонки с анализом речи

Оба участника могут пользоваться нативным Android-приложением или веб-клиентом. Звук идёт через WebRTC. Получатель отправляет копию **удалённой дорожки звонящего** на сервер: PCM → сервер → Google Gemini Live → текст и оценка риска.

**Для звонков используется WebRTC; телефонный номер не нужен.** Это интернет-звонок внутри нашего продукта, не запись SIM/Telegram-звонков и не переадресация. Оба участника должны разрешить анализ. Низкий риск не означает безопасность.

Подключение не требует общего ключа доступа. Любой, кто знает адрес сервера и комнату, может занять свободную роль. Микрофонный диагностический endpoint также доступен без авторизации.

## Границы MVP

- Одна комната, два участника (`caller` и `receiver`), один процесс сервера и один ASR-слот.
- Android — нативный интерфейс на Kotlin и нативный WebRTC SDK; WebView не используется. Адрес сервера задаётся при сборке, пользователь вводит только код комнаты.
- **Android держит соединение в foreground service:** Home, Back, блокировка и поворот больше не завершают разговор. Входящий вызывает системное уведомление с рингтоном. Добавлена доставка через FCM после выгрузки процесса: нужны серверный ключ и обновлённый сервер, см. [настройку Firebase](FIREBASE.md). После принудительной остановки Android нужно открыть приложение. Веб-клиент требует открытой страницы.
- Согласие — только в памяти клиента. В Android сохраняется только код комнаты; ключ Google остаётся на сервере.
- STUN не заменяет TURN: некоторые NAT/мобильные сети не установят прямую связь. Бесплатный TURN проект не предоставляет.
- Потеря ASR явно отмечается; звук может продолжаться. Потеря сигналинга завершает звонок. Пропущенные фрагменты не восстанавливаются.
- Gemini Live обрабатывает речь в облаке Google. Доступ к выбранной модели, квоты и задержка зависят от проекта Google; успешный запуск сервера не подтверждает доступ к модели.

## Запуск на этом компьютере

PowerShell из корня:

```powershell
cd D:\hackaton\SAFETYHACK
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Параметры — [.env.example](.env.example):

```dotenv
PUBLIC_BASE_URL=
RTC_ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"}]
ANALYSIS_MODE=gemini
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.8-live
```

Секреты не коммитить и не присылать в чат. Существующий `.env` автоматически не переписывается.

Создайте Python 3.12+ venv и установите зависимости из lock-файла:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r server/requirements-lock.txt
powershell -NoProfile -ExecutionPolicy Bypass -File server/run.ps1 -Port 8001
```

Официальный SDK Google закреплён в [requirements.txt](server/requirements.txt). [requirements-lock.txt](server/requirements-lock.txt) содержит только установленное замыкание объявленных зависимостей и стандартных extras Uvicorn, проверенное на Windows/Python 3.13.1 (`pip check` успешен). Сетевые ошибки помешали чистому разрешению и проверке Linux/Python 3.12; Linux-only uvloop закреплён по метаданным PyPI, но установка Linux lock ещё не проверена. Локальная модель не нужна. `-Mode diagnostic` отключает анализ. Параметры `-Mode` и `-Model`, если переданы явно, имеют приоритет над окружением и `.env`.

При пустом `PUBLIC_BASE_URL` разрешены localhost-origin:

- Звонящий: `http://localhost:8001/rtc?role=caller`.
- Получатель: `http://localhost:8001/rtc?role=receiver`.
- Проверка: `http://localhost:8001/health`.

Для физического Android нужен доверенный **HTTPS**, не локальный HTTP/IP. Используйте Render или HTTPS-туннель на порт 8001. Запишите точный HTTPS-origin в `PUBLIC_BASE_URL`, перезапустите сервер и открывайте обе страницы через этот домен. При заданном публичном адресе localhost-сигналинг намеренно отклоняется.

## Бесплатный Render

Подготовлены [render.yaml](render.yaml) с `plan: free` и [Dockerfile](server/Dockerfile). Аккаунт/сервис здесь не создавались, платные ресурсы не покупались.

1. Загрузите проект в свой Git-репозиторий **без** секретов, `.tools`, `.venv` и локальных моделей.
2. Создайте Render Blueprint из репозитория либо Web Service: Dockerfile `server/Dockerfile`, context — корень, тариф **Free**, health check `/health`.
3. `PUBLIC_BASE_URL` — реально назначенный HTTPS-origin вида `https://your-service.onrender.com`, без пути. Если адрес ещё неизвестен при создании Blueprint, временно задайте HTTPS-origin, затем исправьте и выполните redeploy **до теста**.
4. В Render Environment задайте `ANALYSIS_MODE=gemini`, секрет `GEMINI_API_KEY` и `GEMINI_MODEL=gemini-3.8-live`. Ключ создайте в Google AI Studio и вводите только на сервере. **Для существующего сервиса вручную удалите старые `ASR_MODE`, `ASR_MODEL`, `ASR_DEVICE`, `ASR_COMPUTE_TYPE`, `ASR_CACHE`**: изменение Blueprint не гарантирует удаления ранее заданных переменных. Удалите старую команду установки Whisper/скачивания модели, если она задана вручную.
5. Дождитесь успешного `/health`. Для Android соберите APK с `-PRTC_BASE_URL=https://ВАШ-ДОМЕН` (тот же origin, что `PUBLIC_BASE_URL`). Веб-клиент по-прежнему доступен по `/rtc`.

Контейнер слушает `0.0.0.0:$PORT`, один worker. TLS/WSS обеспечивает Render. Несколько workers/экземпляров не поддерживаются: комнаты находятся в памяти процесса.

**Бесплатная работа не гарантируется.** Render Free имеет лимиты и может засыпать; Google Gemini имеет отдельные квоты, ограничения региона и тарифа. `gemini-3.8-live` — запрошенный идентификатор, а не подтверждение его наличия или доступа: проверьте поддержку Live API именно для вашего проекта. При ошибке доступа задайте доступную Live-модель явно, не подменяйте её молча. При исчерпании квоты анализ недоступен; diagnostic проверяет только связь. Развёртывание и реальный Gemini-звонок здесь не проверены.


Перед демо разбудите сервис через `/health` и дождитесь готовности. Обновление/перезапуск обрывает звонки. Официально: [Free](https://render.com/docs/free), [WebSockets](https://render.com/docs/websocket), [Docker](https://render.com/docs/docker).

## Android и первый звонок

[APK](android/app/build/outputs/apk/debug/app-debug.apk). Версия исходников: `0.6-push-calls`. Адрес `https://safetyhack-webrtc.onrender.com` уже встроен. Для push-доставки настройте [Firebase и секретный файл Render](FIREBASE.md). Сборка и ограничения: [android/README.md](android/README.md).

1. Установите APK с настроенным сервером. Панель разговора открывается сразу, без ссылки и браузера.
2. Получатель выбирает «Принимаю», создаёт код комнаты и делится им с собеседником.
3. Звонящий выбирает «Звоню» и вводит **тот же код**. Оба подтверждают согласие на анализ и входят в комнату. Веб-клиент также может быть вторым участником.
4. При входе Android запрашивает микрофон и уведомления для фоновой службы. Звонящий нажимает «Позвонить», получатель отвечает в приложении или в системном уведомлении. «Настройки входящих звонков» открывают разрешения уведомлений и полноэкранного показа.
5. Проверьте двусторонний звук, переключение динамика и отключение микрофона. Расшифровка и предупреждения находятся во вкладке «Анализ».
6. Звонящий произносит «Переведите деньги на безопасный счёт». У получателя ожидаются текст и предупреждение; не используйте настоящие коды и персональные сведения.
7. Проверьте отклонение/отмену, завершение с обеих сторон, mute, повторный звонок и потерю сервера. На Android дополнительно проверьте Home, Back, блокировку, поворот, ответ/отклонение из уведомления и отмену входящего звонящим. Завершение вызова оставляет вас в комнате; «Выйти из комнаты» останавливает фоновую службу.

Для двух страниц на одном компьютере используйте наушники, избегайте акустической петли. Такой тест не доказывает работу Vivo или разных сетей.

## Если сигналинг работает, а звук не соединяется

Возможно, нужен TURN. В `RTC_ICE_SERVERS_JSON` можно задать собственный:

```dotenv
RTC_ICE_SERVERS_JSON=[{"urls":"stun:stun.l.google.com:19302"},{"urls":"turns:YOUR-TURN-HOST:5349","username":"YOUR-USER","credential":"YOUR-TURN-PASSWORD"}]
```

Это заглушки, не бесплатный работающий TURN. Участники комнаты получают ICE-учётные данные: используйте ограниченные credentials, не административный ключ. Не отключайте TLS/Origin ради подключения.

## Проверки и безопасность

### Проверка Gemini

Проверьте `/health`, затем выполните согласованный тестовый звонок с несекретной фразой и убедитесь, что получен результат анализа. Готовность HTTP не доказывает доступ к Live-модели. При ошибке проверьте наличие серверного ключа, модель, регион и квоту, не выводя ключи или содержимое разговора в логи. Недоступный анализ нельзя трактовать как низкий риск.

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Фактические результаты — [VALIDATION.md](VALIDATION.md). Автотесты не заменяют разговор на Vivo.

Необязательный браузерный smoke (нужны локальный Chrome и Node Playwright):

```powershell
# Терминал 1: отдельный localhost-сервер, искусственный ASR, без .env/секретов.
.\.venv\Scripts\python.exe -m tests.rtc_browser_smoke --serve-only --slow-first-asr
# Терминал 2: подставьте напечатанный адрес вместо PORT и путь к своему playwright.
node tests/rtc_browser_smoke.cjs /ABS/PATH/TO/node_modules/playwright http://localhost:PORT --busy-redial
```

Этот тест создаёт звуковые тоны и проверяет передачу удалённой дорожки, повторный вызов, busy-retry и очистку. Не измеряет точность Gemini; после проверки остановите тестовый сервер Ctrl+C.

- Сигналинг `/ws/rtc`: ключ в первом JSON по WSS, не в URL. Проверяются Origin, комната, роль, согласие и состояние звонка.
- PCM `/ws/rtc-audio`: одноразовый ticket получателя после принятия звонка. Присланное клиентом аудио не является доверенным доказательством слов человека.
- Сервер не сохраняет аудио/текст на диск. Старый микрофонный тест сохраняет локальный WAV.
- WebRTC шифрует транспорт, но получатель намеренно передаёт удалённый голос серверу и Google Gemini для анализа. Это не обещание доступа только двух участников к содержимому.
